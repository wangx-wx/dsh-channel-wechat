# 事实核查归档：openclaw-weixin 的性质与风险结论修正

> 归档日期：2026-10-08
> 触发原因：本人在上一轮回答中称该协议为「非官方协议 / 有风控风险 / 建议用测试小号」，用户质疑「这是官方开源项目，为什么不安全」。
> 结论：**用户质疑成立，原判断有误，予以撤回。** 本文记录核查过程与修正后的结论。

---

## 1. 原判断（已被撤回）

上一轮我写了：

> 微信协议是**非官方 iLink 接口**……它有账号风控风险，且协议随时可能变。
> 参考项目专门写了熔断和限流，说明高频调用真的触发过限制。建议用测试小号，不要用主号。

**这段判断不成立，撤回。**

---

## 2. 核查证据

### 2.1 项目性质：腾讯官方开源

| 核查项 | 命令 / 来源 | 结果 |
|---|---|---|
| 仓库归属 | `git remote -v` | `https://github.com/Tencent/openclaw-weixin.git` |
| 许可 | `LICENSE` | MIT，`Copyright (C) 2026 Tencent. All rights reserved.` |
| 维护活跃度 | `git log --oneline` | 持续维护至 2.4.9，含 PR 合并、规范化提交历史 |
| 起始时间 | `git log --reverse --date=short` | 2026-03-30 起持续发布 |
| 工程完备度 | 仓库结构 | CI（GitHub Actions）、贡献指南、开发指南、CHANGELOG、覆盖率要求 |

### 2.2 协议文档：官方公开

仓库自带 `docs/protocol_zh_CN.md`（490 行）+ `docs/protocol.md`，开篇即写明：

> 「本文描述 `openclaw-weixin` 渠道插件使用的 HTTP JSON 协议，**面向实现或对接兼容后端的开发者**。」
> 「后端协议文档面向实现或对接兼容后端的开发者。」

即：**腾讯公开此协议文档，目的就是让第三方实现兼容客户端。** 用它写客户端是文档明确预期的用法，不存在「非官方/逆向」性质。

### 2.3 我推理错误的根源

我用 `wechat-claude-code`（**第三方**项目）的防御性代码，去推断官方协议「不安全」：

| 机制 | `wechat-claude-code`（第三方） | `openclaw-weixin`（腾讯官方） |
|---|---|---|
| 发送节流 2500ms | ✅ 有 | ❌ **无** |
| 熔断 30s / 30s 窗口 | ✅ 有（注释写「Borrowed from Hermes WeChat adapter」） | ❌ **无** |
| session 过期暂停 | ✅ 有 | ✅ 有（`errcode -14` → 暂停 1 小时） |

**grep 实证**：官方 `src/` 全目录中，限流相关实现只有 `src/api/session-guard.ts` 的一小时冷却，且其文档说明是「`errcode -14` 时触发一小时的账号会话暂停」，即**处理 token 过期，不是防高频**。

所以：
- 「官方项目专门写了熔断限流」→ **事实错误**，写熔断的是第三方项目。
- 「说明高频调用真的触发过限制」→ **推理无效**，该结论不能从第三方项目的自保代码推出官方服务端的行为。

## 3. 修正后的风险结论

### 3.1 不成立的说法（撤回）

- ❌ 「非官方协议」——腾讯官方仓库 + 官方公开协议文档。
- ❌ 「有账号风控/封号风险」——在已核查的证据中**没有依据**。官方插件不节流地直发，官方文档也未提及配额或封禁机制。
- ❌ 「建议用测试小号」作为**安全必需项**——这一点降级为「谨慎偏好」，见 3.3。

### 3.2 真实存在的风险（量级小得多）

**风险 A：协议文档自述的完备性边界（真实且重要）**

官方文档明确声明其描述范围的限制：

> 「客户端类型和行为**不能代表完整的服务端契约**。尤其是，TypeScript 字段标记为可选，不代表服务端一定接受省略该字段的请求；类型中定义了某个字段，也不代表插件已经实现所有相关能力。」
> 「超出这些源码所体现范围的服务端要求，需要**另行验证**。」

含义：文档描述的是**当前插件怎么用**，不是完整服务端规范。自行实现客户端时，插件未覆盖的边界行为（如某字段服务端实际必填、错误码分支）需实测确认。

**这是文档完备性问题，不是安全性问题。**

**风险 B：会话会真实过期（真实）**

`errcode -14` 表示 bot token 失效，官方处理为暂停 1 小时后需重新扫码。这不是风控，是会话生命周期。插件必须对齐处理。

**风险 C：协议会演进（真实但可控）**

官方有 `assertHostCompatibility(api.runtime?.version)` 做版本门禁，`channel_version` 随包版本变化。协议字段可能随版本增删。应对：实现版本探测，失败时**明确报错**而非静默降级。

### 3.3 降级保留的建议

「用测试号」从**安全必需**降为**工程谨慎**：开发调试期用测试号，可避免把调试消息发给真实联系人，与安全性无关。

## 4. 对设计方案的影响

原方案 [dsh-wechat-plugin-design.md](./dsh-wechat-plugin-design.md) 的以下部分需修正：

| 位置 | 原文 | 修正 |
|---|---|---|
| §0 摘要「必须先确认的分歧」 | 称协议非官方、有风控 | 删除该警告；改为「协议为腾讯官方公开文档，按文档实现即可」 |
| §2.6 稳定性要点 | 把 2500ms 节流、30s 熔断列为「必须复刻的坑」 | 降级为**可选自保措施**，进 `Config` 可调项；官方不节流说明直发可接受 |
| §8 高风险 1 | 「非官方协议 + 风控」 | 替换为「协议文档只覆盖插件已用部分，边界行为需逐条对齐 + 实测」 |
| §8 高风险 2 | 「协议随时可能变」 | 保留，但补充官方有版本门禁机制可参考 |
| §8 建议 | 「建议用测试小号（安全）」 | 改为「开发期用测试号（工程谨慎，非安全必需）」 |

### 方案主体不受影响

- 自行实现协议层、不依赖 OpenClaw 运行 —— **不变**
- 三层架构（协议层 / 桥接层 / ctx.agents）—— **不变**
- DSH 侧的全部约束（不做 bin、注册即 effect、模型可见⟺logged 等）—— **不变**

---

## 5. 结论

1. **`openclaw-weixin` 是腾讯官方的 MIT 开源项目，附带官方公开的协议文档，明确面向兼容实现者。** 用它写第三方客户端是正当且被文档预期支持的用法。
2. **我原先的「非官方 + 风控」判断是把第三方项目的防御代码误投射到官方项目上，属于事实错误，正式撤回。**
3. 真实需要关注的不是「安不安全」，而是**协议文档的覆盖面小于服务端实际契约**——这要求在 P0 阶段以官方文档为规范、并逐条实测验证边界行为。
4. 「用测试号」保留为开发期工程建议，不再作为安全警告表述。

## 附：官方协议速查（据 `docs/protocol_zh_CN.md`）

**Base**：`https://ilinkai.weixin.qq.com`；**CDN**：`https://novac2c.cdn.weixin.qq.com/c2c`

**请求头**

| Header | 值 |
|---|---|
| `Content-Type` | `application/json` |
| `AuthorizationType` | `ilink_bot_token` |
| `Authorization` | `Bearer <bot_token>` |
| `X-WECHAT-UIN` | 随机 uint32 十进制字符串再 base64 |
| `iLink-App-Id` | 目前为 `bot` |
| `iLink-App-ClientVersion` | 版本按 `0x00MMNNPP` 编码十进制字符串 |
| `SKRouteTag` | 可选路由标签 |

**接口总览**

| 操作 | 方法与路径 | 用途 |
|---|---|---|
| `getUpdates` | `POST /ilink/bot/getupdates` | 长轮询取消息（建议超时 35000ms） |
| `sendMessage` | `POST /ilink/bot/sendmessage` | 发消息 |
| `getUploadUrl` | `POST /ilink/bot/getuploadurl` | 取媒体上传参数 |
| `getConfig` | `POST /ilink/bot/getconfig` | 取配置与 typing ticket |
| `sendTyping` | `POST /ilink/bot/sendtyping` | 输入状态（1 开始 / 2 取消） |
| `notifyStart` | `POST /ilink/bot/msg/notifystart` | 通知后端客户端启动 |
| `notifyStop` | `POST /ilink/bot/msg/notifystop` | 通知后端客户端停止 |

**登录**

```
POST /ilink/bot/get_bot_qrcode?bot_type=3      body: { local_token_list: [] }（最多 10 个）
GET  /ilink/bot/get_qrcode_status?qrcode=<值>[&verify_code=<值>]
```

状态机：`wait` / `scaned` / `confirmed` / `expired` / `need_verifycode` / `verify_code_blocked` / `scaned_but_redirect`（切 `redirect_host`）/ `binded_redirect`（已绑定其他实例）

`confirmed` 返回：`bot_token`、`ilink_bot_id`、`baseurl`、`ilink_user_id`

**消息模型**

`WeixinMessage` 关键字段：`message_id`、`from_user_id`、`to_user_id`、`message_type`（1 用户 / 2 Bot）、`message_state`（0 新 / 1 生成中 / 2 完成）、`item_list`、`context_token`、`run_id`

`MessageItem.type`：1 text / 2 image / 3 voice / 4 file / 5 video / 11 tool_call_start / 12 tool_call_result

**CDN**

- 上传：明文 MD5 → 16 字节 AES key + filekey → `getUploadUrl` → AES-128-ECB/PKCS#7 加密 → `POST` 密文（`application/octet-stream`）→ 取响应头 `x-encrypted-param`
- 下载：优先 `full_url`，否则 `<cdn_base>/download?encrypted_query_param=<URL编码>`
- 图片密钥优先 `image_item.aeskey`（32 位 hex），其次 `media.aes_key`
- 成功判定：HTTP 200 **且** `x-encrypted-param` 非空；4xx 立即终止，其他失败最多 3 次
