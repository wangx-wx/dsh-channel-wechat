## 9. 对本项目的兼容性结论

`dsh-channel-wechat` 当前 peer 钉在 `0.2.0-rc.1`。逐项核对结果：

| 检查项 | 结论 |
|---|---|
| 24 个 peer 包是否存在 | 全部存在；`dsh-cmdline` → `packages/boot/cmdline`、`dsh-session` → `packages/core/session` 仅路径搬家，包名不变 |
| `{{cwd}}` 变量移除 | 本插件不设 `personaSuffix`，仅 `cordis.patch.yml` 注释提及；配置层安全 |
| `engines.dsh` 优先规则 | 本包只声明 `engines.node`，走 peer 回退分支，不受影响 |
| 存储凭据优先级 | 本插件用 `ctx.credentials` 的 record API 存微信登录；headless profile 默认不挂载存储认证，headless 场景读不到登录态——**需实测** |
| `tool-presentation-mode` | 本插件不声明 `mode`，无影响 |
| subagent activations / JobId | 本插件不用 `job_output`/`job_kill` 收集子 agent，无影响 |
| `session/event` 新事件 | 多出 `job/*`、`working-directory/change`，`onSessionEvent` 按类型白名单匹配，安全忽略 |
| `presentedFilesFrom` 的 cwd 语义 | **行为变好**：0.2.0-rc.1 的 present 工具原样写入模型给的路径（可能是相对 header cwd 的），本插件用 `session.header.cwd` 拼接；0.2.1-rc.1 起工具改用 `ctx.workingDirectory.ensure()` 解析并写入 `ctx.fs.processPath(target)` 的**绝对路径**，本插件的 `resolvePath` 对绝对路径原样返回（见 §7 附注） |
| 会话创建 | `create({ meta: { cwd } })` 与 `resume({ resumeSessionId })` 签名未变；`agentPresets.resolve/mount` 未变 |
| 卡片 | `approval/request`、`user-questions/request` 的 waterfall 与 `{ prepend: true }` 语义未变 |
| 命令 | `ctx.commands.execute/list` 未变 |
| invariant 体系删除 | 本插件无 `./invariant` 导出、无 `INVARIANT` 码路径，无影响 |

**唯一需要留意的行为偏移**（且方向是变好）：0.2.0-rc.1 的 `present` 工具把模型给的相对路径原样写进 `deliverables/presented`（相对 `header.cwd`），本插件按 `header.cwd` 拼接，语义一致。0.2.1-rc.1 起该工具改用 `ctx.workingDirectory.ensure()` 解析，并写入 `ctx.fs.processPath(target)` 的**绝对路径**（`files.push({ ...file, path: ctx.fs.processPath(target) })`），本插件的 `resolvePath` 对绝对路径原样返回，因此不需要改动；反而在模型先 `working_directory({cd})` 再 `present("out.md")` 的场景下，旧版会拼错、新版自洽。

附注（同一类风险仍存在）：若某个第三方工具自行 append `deliverables/presented` 且写相对路径，本插件会按 `header.cwd` 解析，而事件契约（`PresentedFile.path`：`Original absolute path or path relative to the Session working directory`）里的「working directory」在 0.2.1 已指当前目录而非 header。这不是本版本崩溃点，但值得在 `deliverables.ts` 注释里改口径。
