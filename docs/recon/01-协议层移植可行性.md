**决定因素**：5467 行测试可作为移植后的回归基线。wcc 仅作**差分对照物**。

## 5. 两实现不一致点（需真机判定，20 项摘要）

| # | 主题 | openclaw-weixin | wechat-claude-code |
|---|---|---|---|
| 1 | 发送限流/熔断 | **无** | 2500ms 间隔 + 退避 + 熔断 |
| 2 | getUpdates 过期 | `ret` 或 `errcode` 为 -14 | 仅 `ret === -14` |
| 3 | 非零 ret | 不保存 buf，退避重试 | 仍保存 buf 并继续 |
| 4 | 退避 | 3 次失败→30s，否则 2s；消费 `longpolling_timeout_ms` | 3 次→30s，否则 3s；固定 35s |
| 5 | 去重 | **无** | Set 上限 1000 |
| 6 | 并发模型 | 串行 await（阻塞轮询） | fire-and-forget |
| 7 | PKCS7 尺寸 | `ceil((n+1)/16)*16` ✅ 正确 | `floor((n+15)/16)*16` ❌ n=16 时少一块 |
| 8 | 图片 AES key 优先级 | `image_item.aeskey` 优先 ✅ | 注释称 `media.aes_key` 优先 ❌ |
| 9 | base_info 覆盖 | 全部 bot POST | 仅 getUploadUrl，且硬编码版本 |
| 10 | notifyStart/Stop | 有 | 无 |
| 11 | QR 登录 | 35s 轮询/1s 间隔/3 次刷新 + 重定向 + 验证码 | 60s/3s，expired 抛错 |
| 12 | client_id | `openclaw-weixin:{ts}-{8hex}` | `wcc-{ts}-{counter}` |
| 13 | message_id | **字符串无损**（uint64 重写） | `number`（大 ID 丢精度）❌ |
| 14 | 文本分片 | 交给框架 4000 上限 | 自实现 4000 切分 |
| 15 | typing 保活 | 框架回调 5s | 自实现 5s |
| 16 | CDN 上传重试 | 3 次，含响应头缺失 | 3 次，超时不重试 |
| 17 | 文件大小上限 | 仅 quote 缓存生效 | 上传显式 25MiB 校验 |
| 18 | sync_buf 位置 | 每账号一文件 | 单文件 |
| 19 | **加密参数顺序** | `encryptAesEcb(plaintext, key)` | `encryptAesEcb(key, plaintext)` |
| 20 | run_id | 出站携带 | 无 |

**倾向**：7、8、13 明显是 openclaw-weixin 正确。其余（尤其 1、3、5、6）**无法仅凭源码判定**，需真机抓包或实测。

**重要限制**：`openclaw` 包未安装，`plugin-sdk` 各子路径的实际导出与语义未核实；`docs/protocol.md` 亦声明「客户端类型不构成完整服务端契约」。

## 6. 对本项目的影响

1. **Q2 若选「自己实现协议」**：不以直接复制为目标，而是**以官方实现为规范参照**，重点对齐第 5 节中倾向正确的项（7/8/13），并把不一致项（1/3/5/6）列入 P0 实测清单。
2. **`markdown-filter.ts` 与 `textChunkLimit:4000`** 值得注意：官方把分片交给框架，我们需自实现，可参考 wcc 的 card-aware 切分。
3. **移植是选项而非前提**：官方无 npm 协议库、且强 peer `openclaw`，所以不能直接 `npm install` 复用，必须复制或重写。许可 MIT，需保留署名。
