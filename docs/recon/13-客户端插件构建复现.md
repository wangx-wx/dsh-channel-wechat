## 3. `/plugins` 加载协议（`packages/client/modules`）

**Host 侧**
- constructor 同步扫描所有 loader entries（`src/index.ts:636-645`）→ 读 `package.json` → `parseDshClient`（`manifest.ts:161-181`，**要求 `platform === 'web'`**）→ `clientExportOf` 取 `exports["./client"]`（`index.ts:195-205`，string 或 `{default:string}`）
- 缺文件 → 抛 `MissingClientBundleError`（`index.ts:95-110`）
- 路由 `/plugins`；combo `/plugins/??<id>/client.js&rev=`；chunk `/plugins/<id>/client.<name>.js?rev=`
- `rev = sha1(mtime,ctime,size)` 前 12 位

**浏览器签名**（`src/client/manifest.ts:316-328`）：
```ts
load({ id: string, chunk?: string, factory: (require) => exports })
```
- 执行 bundle **只注册**；`factory` 首次 import 时 materialize 一次（`system.ts:293-315`）
- 重复注册抛错；`id` 会 stripClientSuffix；chunk 名必须匹配 `/^client\.[A-Za-z0-9][A-Za-z0-9._-]*\.js$/`

**6 条硬性要求**
1. 必须 `load({id, ...})` 且 `id` = **包名**
2. entry **单文件自包含**，不能有相对 `require("./client*.js")`
3. 动态 chunk 只能 `require.async('./client.x.js')`
4. `require` 的字面量必须在 seed(9) + `dsh.client.external` 内
5. `exports["./client"]` 文件必须真实存在
6. source map **非必需**

**失败表现**：几乎全有报错（缺文件→Host 激活抛错；执行但未注册→"loaded without registering"；require 未知→"missed the module table"）。**仅 `platform !== 'web'` 或未声明 `dsh.client` 是静默不进图。**

## 4. ★ 最小可行方案（子任务**实测通过**）

探针位置：`/Users/wangx/cc/probe`（用 DSH 自带 tsdown 0.22.2 + rolldown 1.1.1）

**方案 A（推荐）：抄 `clientConfig` 字段成自己的 `tsdown.config.ts`**

```ts
export default [{
  name: `${id}/client`,
  entry: { client: 'src/client/index.ts' }, outDir: 'lib',
  format: 'cjs', platform: 'browser', target: 'es2024',
  dts: false, clean: false, sourcemap: true, fixedExtension: false,
  deps: { neverBundle: s => EXTERNALS.has(s), alwaysBundle: s => !EXTERNALS.has(s) },
  inputOptions: { resolve: { conditionNames: [NODE_ENV === 'development' ? 'development' : 'production', 'browser', 'import', 'module', 'default'] } },
  define: {
    'process.env.NODE_ENV': JSON.stringify('production'),
    'import.meta.env.MODE': JSON.stringify('production'),
    'import.meta.env': JSON.stringify({ MODE: 'production' }),
  },
  plugins: [asyncChunkRequirePlugin(), ...cssPlugins],
  outputOptions: {
    entryFileNames: 'client.js',
    chunkFileNames: 'client.[name].js',
    banner: () => `window.__ModuleLoader__.load({ id: ${JSON.stringify(id)}, factory: (require) => {`,
    footer: 'return module.exports; } });',
    intro: 'var module = { exports: {} }; var exports = module.exports;',
  },
}]
```

**实测结论**：
- 基础入口 / TSX **通过**
- **必须**加 `chunkFileNames` + `renderChunk` 重写插件：`import('./heavy')` → `lib/client.heavy.js` + `require.async("./client.heavy.js")`；不加则产出哈希名 `heavy-xxx.js`，**CLIENT_CHUNK 不接受，必然失败**
- **必须**复制 3 个 CSS 虚拟 loader：`.module.css` 得到哈希类名 + `<style data-plugin>` 注入；不复制则 tsdown 直接报 `"@tsdown/css is not installed"`

**方案 B（esbuild 包一层）**：实测 `format:'cjs'` + banner/footer 能出可加载产物，但**动态 import 无法重写、CSS 会输出独立文件（模块表不加载会丢）、externals 要自己重写** → 可行但不省事，仅在拿不到 tsdown 时用

**方案 C（完全手写）**：适合**纯 JS 小插件**（官方模板 + `dsh-wechat` 都证明可行），不适合我们「有 `src/client/index.ts`」的场景

## 6. `dsh.client.inject` 的语义

- 类型文档（`package-manifest/src/types.ts:84`）：
  > "Informational package-name dependencies, **not Cordis service injection**."
- 加载期（`modules/src/client/system.ts:246-273`）：外部依赖先加载；`inject` 只在 `graphRows.get(packageName) !== undefined` 时让对方的 factory 先到位
- **声明了但图里没有该行 → 静默跳过**（测试钉死：`tests/loader.client.spec.ts:889-897`）
- **真正的 Cordis 服务注入是插件自己导出的 `inject`**（如 `export const inject = ['slots']`）：服务不存在 → fiber **PENDING**，不失败但**激活不了**，boot audit 报 `pending (waiting for service: X)`
- `slots` 服务由 `ui-renderer` 提供

## 7. 对方案的决策含义

1. **格式唯一硬要求**：单文件自包含 `window.__ModuleLoader__.load({id:"<包名>", factory:(require)=>{...}})`
2. **`clientBundle` = 普通 tsdown 配置 + 3 个自写插件，可完整复刻** —— 已有实测通过的可复制配置
3. **externals 只能是 9 个基线 + 自己的 `dsh.client.external`**，其余全内联
4. **编译型包用方案 A（tsdown）**；纯 JS 小插件可方案 C（手写）
5. ⚠️ **仓库内的构建期纯度门在仓库外不可用** → 需自行约束，否则退化为**浏览器运行时报错**
6. **`dsh-wechat` 的先例说明**：手写 + 拷贝也能被 npm 接受，且**完全复用 DSH slot 系统**（不是自建 UI）
