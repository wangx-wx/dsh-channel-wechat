# 侦察报告 10：微信 ClawBot 群聊可行性（Q18 之一）

> 来源：子任务 c3525b2e（只读核查）
> 结论：**无任何官方声明/协议/实现支持群聊** → 群聊不是"难做"，而是"没有依据可做"

## 1. 协议层：字段存在，但文档主动声明「字段 ≠ 功能」

`WeixinMessage` 群相关字段（`src/api/types.ts:192-209`）：
- `group_id?: string`（`:203`）—— `docs/protocol_zh_CN.md:397`「适用于群聊的群 ID」
- `session_id?: string`（`:202`）—— 「会话 ID」
- **无 `chat_type` 字段**（全仓 grep 零命中）

**★ 关键声明**（`docs/protocol_zh_CN.md:382`）：
> 「`group_id` 等字段**只表示类型定义包含该字段，不保证插件支持对应功能**」

英文版 `docs/protocol.md:382` 同义；`protocol_zh_CN.md:15` 再次强调。

**无群聊章节/示例/限制说明**：全文 25 个标题索引无一条关于群；`group_id` 在表外正文**零提及**。

**出站**：`SendMessageReq.msg?: WeixinMessage` 未排除 `group_id`，但**源码零处给 `group_id` 赋值**。`send.ts:57-80,154-159,218` 均只写 `to_user_id`。
→ 「`to_user_id` 能否填群 id」**仓库内无法证实也无法证伪，无依据**。

## 2. 官方实现：6 处硬编码单聊

| 位置 | 内容 |
|---|---|
| `channel.ts:230` | `chatTypes: ["direct"]` |
| `channel.ts:268` | `outbound.deliveryMode: "direct"` |
| `channel.ts:242-243` | 注释「Weixin user IDs always end with @im.wechat; **treat as direct IDs**」 |
| `inbound.ts:151,266` | `ChatType: "direct"` |
| `process-message.ts:193,210` | `isGroup: false` ×2 |
| `process-message.ts:260` | `peer: { kind: "direct", id: ctx.To }` |

- `git log -S chatTypes --all`：自**首个提交** `27ee4b4 (v1.0.1, 2026-03-30)` 起**从未改动**
- `process-message.ts:196` `configuredGroupAllowFrom: []`
- **无「未实现/暂不支持/计划中」声明**：CHANGELOG（中英）「群/group」命中 **0**；README 唯一相关是「隔离**私聊**会话」

## 3. 入站不区分单聊/群聊

`inbound.ts:250-267`：`From = To = OriginatingTo = from_user_id`（`:258,259,262`），`ChatType: "direct"`（`:266`）。
**实际只用 `from_user_id`**；`group_id` 从未读取；`to_user_id`/`session_id` 不参与路由鉴权（`session_id` 仅 debug 日志 `:121`）。

## 4. 群内输入状态：语义未定义

`SendTypingReq.ilink_user_id` 在 `docs/protocol_zh_CN.md:329-349` 只写「<用户 ID>」，**无群说明、无 group_id**。官方调用 `process-message.ts:337,349 ilink_user_id: ctx.To`（= `from_user_id`），ticket 也按用户取。
→ **群语义未定义，无证据可行。**

## 5. 唯一群相关线索（属作者陈述，非协议事实）

`wechat-claude-code` 提交 `6a64085`（2026-06-09，`fix: verify sender identity to prevent unauthorized access`，Fixes #23）正文提到：
> 「ignoring messages from anyone else (**e.g. group members @-ing the bot**)」

对应代码 `src/main.ts:357`：`if (account.userId && msg.from_user_id !== account.userId) return;`

**更保守读法**：存在该投递，但该代码本身是「丢弃非绑定用户」= **主动单聊化**。

该项目的 `src/wechat/types.ts:77-87` **连 `group_id`/`session_id` 都没有**。

## 6. 证据等级与局限

| 等级 | 内容 |
|---|---|
| **文档明说** | `group_id` 存在及含义（`protocol_zh_CN.md:397`）；但**字段≠支持**（`:382,15`）；`ilink_user_id` = 用户 ID（`:337`） |
| **代码事实** | 6 处硬编码 direct；**全仓零读写 `group_id`**；身份全用 `from_user_id` |
| **未找到证据** | 官方「群聊未实现/计划中」声明；群协议章节/示例/限制/`chat_type`；`to_user_id` 填群 id 是否有效；群内 typing 是否可行 |
| **推测（勿当事实）** | 若服务端投递群消息会被当私聊回给发送者；`6a64085` 暗示群投递存在 |

### ⚠️ 本次核查的局限（必须记录）

- `web_search` 因 **HTTP 401 不可用**
- registry / github 域名被解析为**非公网 IP**，`web_fetch` 全部被拒
- ⇒ **外部公开证据未能核验**

**严格结论**：「仓库内无支持依据」，而非「世界上一定不支持」。要判定群聊能否做，**必须先向腾讯 iLink 确认服务端契约**（`to_user_id` 能否填群 id、有无群专用字段、`sendTyping` 群语义）。

## 7. 决策含义

**建议把群聊从差异化点中划掉。**

理由：不是工程量问题，而是**没有依据**——官方文档主动声明字段不保证功能，实现从未触碰，协议未定义。在缺少服务端契约确认前做群聊，等于在猜测上盖房子。

若未来确需群聊：先向腾讯确认契约，再评估。
