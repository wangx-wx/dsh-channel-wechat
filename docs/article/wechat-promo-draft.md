# 你的大肥鱼，现在住在微信里


## 开头

![微信里的审批卡](../assets/readme/approval-card.jpg)

这是一张微信截图。

对话的另一头不是人，是我电脑上跑着的 DeepSeek Harness。我让它看看某个目录里有什么文件，它发现那个目录权限不够，于是**在微信里给我弹了一张审批卡**，问我允不允许。我回了一句 `P11`，它继续干活。

整个过程，我没有碰过电脑。

这就是 `dsh-channel-wechat` 这个插件在做的事——**把大肥鱼接到微信里**。

---

## 一、先说清楚它是什么

DeepSeek Harness（下面就叫大肥鱼）是 DeepSeek AI 开源的一个 agent harness，跑在你本机，能读写文件、跑命令、调用技能。

- **项目地址**：`https://github.com/deepseek-ai/deepseek-harness`
- **文档站**：`https://deepseek-harness.github.io/deepseek-harness/`

它的架构是「一切皆插件」（everything-is-a-plugin），所以微信能被做成它的一个通道。

`dsh-channel-wechat` 就是一个通道插件：它让大肥鱼多了一个"微信"这个出入口。你在微信发消息，消息进入大肥鱼的会话；大肥鱼干完活，回答回到微信。

它是一个 npm 包，`dsh plugin add` 一行装完，运行在大肥鱼进程内部，不额外起一个常驻的桥接程序。

**一句话：电脑还是主体，微信是遥控器。**

## 二、三段真实的使用流程

### 第一段：随口问一句

![微信里与大肥鱼的对话](../assets/readme/wechat-chat.jpg)

我发「当前在什么目录」，它回答工作目录在哪、这个目录是什么权限范围，还主动问要不要看看里面有什么。

不用切到电脑前，不用打开浏览器，不用记任何命令。

### 第二段：它要权限的时候，卡片直接进微信

就是开头那张图。

大肥鱼执行工具前需要确认时，审批卡会转发到微信：工具名、原因说明、可选项、怎么回复，一屏说清楚。回一个编号就继续。

**这是我觉得这个插件最不一样的地方。** 市面上把 AI 接进微信的项目不少，但大多数只是"问答"。而 agent 真正的门槛从来不是问答——是它要动你的文件、跑你的命令时的那一次授权。这一步能在微信里完成，"人不在电脑前"才真的成立。

提问卡同理，它需要你选一个方向的时候，也会送到微信。

### 第三段：真正让它干活

![插件配置页](../assets/readme/plugin-page.jpg)

插件页在大肥鱼的 GUI 里，扫码登录、填工作目录、选权限和模型，都在这一页。

微信里还能直接发命令：

| 命令 | 作用 |
|---|---|
| `/help`、`/h` | 看有哪些命令和技能 |
| `/cwd <绝对路径>` | 换到另一个项目目录开新对话 |
| `/models`、`/model <provider/model>` | 查模型、换模型 |
| `/skills` | 列出可调用的技能 |
| `/stop` | 打断正在生成的回复 |
| `/status` | 看登录账号和会话数 |
| `/new` | 结束当前会话，下一条开新对话 |

特别说说 `/cwd` 和 `/model`：

- `/cwd` 切换目录会**结束当前会话、在新目录开始新对话**，历史不会跟过去（大肥鱼的会话目录创建后不可改）。切换结果跨重启保留，不会哪天悄悄退回默认目录。
- `/model` 改的只是微信会话用的模型，不影响 GUI，也不用 `/new`，下一条消息就生效。写错模型名会当场报错，不会悄悄写进配置。

## 三、优势在哪

功能清单其实谁都能列。我更想讲三个**别人不太愿意讲、但我们写进测试里**的地方。

### 1. 消息不会丢

这是这个插件的核心目标，也是开发中花时间最多的部分。三个具体的失败模式：

**第一个：整轮跑完了，微信一条回复都没有。**
听起来离谱，但只要回复挂在错误的生命周期上就会发生——大肥鱼一轮里会产出旁白、工具参数、最终回答，订阅错了地方，你收到的就是一片空白。我们订阅的是 durable 的会话事件，只发最终回答。

**第二个：回复太长，整条被服务端拒绝。**
微信单条消息有长度上限。超长回复现在按段落切开分多条发送，代码围栏会补闭合再重开，不会切一半就断在代码块里。

**第三个：发太快被限流，然后静默消失。**
微信服务端对突发发送会返回 `ret: -2`。我们的做法是主动调速，被限流时按 2s → 4s → 8s → 16s 退避重试，而不是重试三次失败就当没这回事。

这三条都有测试钉着，改坏了 CI 会红。

> 用别人的工具，你可以容忍功能少一点，但容忍不了"它到底有没有干活"这件事说不清。

> 【配图位：建议做一张 6 秒内的 GIF，展示发消息 → 微信顶部出现「对方正在输入」→ 回复到达】

顺带一提：它正在生成的时候，微信顶部会显示**「对方正在输入」**。等待有反馈，比转圈强。

### 2. 只有你扫码登录的那个号能用

这是 v0.2.7 加的，我认为值得单独讲。

默认情况下，**只有扫码登录的那个微信号**能驱动这个机器人。其他人发来的消息：不建会话、不执行命令、不回复任何内容，只在日志里留一行记录。

这不是"防止别人跟你聊天"这种小问题。同一条入站路径上还能执行 `/model`（改你的配置）、`/cwd`（把会话迁到任意目录）和宿主命令——不限制的话，任何能给这个机器人发消息的人，都能改你的配置。

如果确实要分给同事或家人，插件页的「允许使用的人」里一行填一个微信 id 就行。填了之后以名单为准，扫码登录的人不再自动包含在内。

**所以你可以放心把手机借给别人。**

### 3. 出站文件只发它自己声明要交付的

你说"帮我整理一下文件"，它整理完，**只把明确声明要交付的文件发给你，不会扫一遍工作目录全传过来**。

这条听起来像小事，但它决定了你敢不敢让它碰真实的工作目录。

## 四、也有它做不到的事

诚实很重要，免得你装完了骂我。

**电脑得开着。** 大肥鱼跑在你本机，微信只是收发的通道。合盖睡眠、关机、断网，就是断了。这不是云端服务，别按云端的预期用。

**它不是腾讯官方产品。** 底层的微信协议来自腾讯官方开源的 `openclaw-weixin`（MIT 许可，腾讯公开此协议正是为了对接第三方客户端），但这个插件是我个人维护的第三方项目，跟腾讯没关系。

**范围外的东西：** 群聊、运行期多账号、主动推送、独立权限系统，目前都不做。

**大肥鱼自己还在 developer preview。** 迭代很快，会有破坏性变更。插件跟着它的版本走，所以请把两边都保持较新。

**审批卡的第 3 个选项会关掉当次会话的审批。** 「本会话全部权限」等于把会话切到 `danger-full-access`，之后不再弹卡，`/new` 之后恢复。方便是真的方便，风险也是真的风险——尤其它现在能在微信里被点到。

**`/cwd` 和沙箱边界不完全联动。** 换目录后会话的 `cwd` 变了，但沙箱写入边界读的仍是会话创建时的目录。跨目录写入需要改权限，这个坑文档里写了。

## 五、怎么装

![插件配置页](../assets/readme/plugin-page.jpg)

分两段：先把大肥鱼装起来，再给它加微信。

### 第一段：装大肥鱼（已经装了可以跳过）

**项目地址：`https://github.com/deepseek-ai/deepseek-harness`**

**文档站：`https://deepseek-harness.github.io/deepseek-harness/`**

最省事的方式是直接跑 npm 包，需要先装好 Node.js：

```
npx @deepseek-ai/dsh web
```

这条命令会在本机启动 Web UI，默认地址 `http://127.0.0.1:3080`，并自动打开浏览器。加上 `--no-open` 就只启动服务、不弹浏览器。

想从源码跑：

```
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web
```

源码方式需要 pnpm 11。跑起来之后，你就有 profile 了——插件装在这个 profile 上。

> **提醒一句**：大肥鱼目前是 developer preview，官方明确说了会有破坏性变更。跑之前建议先看一眼仓库里的 `SAFETY.md`。它是能读写你文件的工具，别拿它对着重要目录瞎试。

### 第二段：装微信插件

前置条件：大肥鱼版本 `>= 0.2.0-rc.1`，Node.js `^22.19.0` 或 `>= 24.0.0`。

**第一步，确认你有一个大肥鱼 profile，并且知道要给它用的工作目录（必须是绝对路径，且存在）。**

**第二步，装插件：**

```
dsh plugin --profile 你的profile名 add dsh-channel-wechat
```

**第三步，完全退出并重开大肥鱼。** 宿主的浏览器模块图有缓存，不重启看不到配置页。

**第四步，打开 GUI → 插件 → dsh-channel-wechat，点登录，手机扫码。**

**第五步，从微信发一条消息，确认回复能回到微信。**

就这五步。

如果刚发布的版本被 pnpm 的观察期跳过，加一个参数：

```
dsh plugin --profile 你的profile名 add dsh-channel-wechat@latest --config.minimumReleaseAge=0
```

### 升级有个坑，一定要知道

`add` 不会替你升级：

```
dsh plugin --profile 你的profile名 add dsh-channel-wechat
# reused 5, downloaded 0   ← 一个包都没下载，还告诉你成功了
```

已有的版本范围本来就被新版本满足，包管理器判定"无需变更"，原样装回旧版。正确做法是先删再装：

```
dsh plugin --profile 你的profile名 remove dsh-channel-wechat
dsh plugin --profile 你的profile名 add dsh-channel-wechat@0.2.7
```

装完同样要完全重启。

## 六、遇到问题怎么办

先看插件日志：

```
~/.dsh/channel-wechat/log/channel-wechat-YYYY-MM-DD.log
```

保留 7 天。消息没回复，先查日志、账号状态、`cwd` 是不是绝对路径，这三样能解决绝大多数问题。

还没解决，去 GitHub 提 Issue。**提之前请准备好**：大肥鱼版本、插件版本、profile 类型（web / desktop）、复现步骤、脱敏后的日志。

**不要贴 token、Cookie 或凭证文件内容。**

## 七、写在最后

这个插件最早只是我自己想在地铁上让大肥鱼干点活。

做到后面发现，真正难的不是"打通微信"——协议文档是公开的，扫码、长轮询、发消息，都是明面上的活。难的全是**错了不会报错**的地方：消息发出去了但没人收到，整轮跑完了但回复丢了，卡片弹出来了但回复被当成普通消息吃掉。

所以这个仓库里测试写得比功能多。你不一定能直接从代码里看出这一点，但用起来会。

如果你也在用大肥鱼，也想过"要是在微信里就能用就好了"，可以直接装来试试。
