# 微信内命令

在微信聊天里直接发送以 `/` 开头的消息。两类命令在处理方式上不同：

- **本插件的命令**在通道内处理，不会发给模型，也不消耗 token。
- **DSH 的命令**原样转发给 harness，由会话所在 agent 执行。

不确定有哪些可用时，发送 `/help`（或 `/h`）。

## 本插件命令

| 命令 | 作用 |
|---|---|
| `/help`、`/h` | 列出本插件命令和当前会话可用的 DSH 命令，并显示当前工作目录 |
| `/status` | 查看当前登录账号与已建立会话的数量 |
| `/stop` | 中断正在生成的那条回复，并作废该会话所有待确认的卡片 |
| `/new` | 结束当前会话，下一条消息开始新对话（回复中会说明新会话的工作目录） |
| `/cwd` | 查看当前工作目录 |
| `/cwd <绝对路径>` | 切换到该目录：结束当前会话，下一条消息在新目录开始新对话 |
| `/skills` | 列出可调用的技能名称 |
| `/models` | 列出可用的供应商与模型，并标出当前配置 |
| `/model <provider/model>` | 切换本插件使用的模型 |
| `/reconnect` | 已注册，尚未实现 |

`/new` 不会删除聊天记录：会话 id 只增加代次，旧会话文件保留在磁盘上。

## `/cwd`：切换工作目录

会话的 `cwd` 在创建时写入，**之后不可修改**。所以「切换工作目录」只能是**结束当前会话、在新目录开始新对话**，
历史不会跟过来。

```
/cwd D:\workspace\my-project
```

- **只接受绝对路径**。相对路径会被拒绝：进程自己的目录在手机上不可见，解析出来的位置和你以为的不是一回事。
- 目录必须**已存在**。本插件不会替你创建——否则打错字会得到一个新建的空目录，而不是你想进的项目。
- 路径会先规范化（解析 `..` 与符号链接）再写入，避免同一个目录出现两种写法。
- 切换后**下一条消息**在新目录开始新对话；旧对话仍在磁盘上。
- 新目录会跨重启保留（存在 `~/.dsh/channel-wechat/peer-sessions.json`），不会因为重启被悄悄退回配置里的默认目录。

不给参数时只报告当前目录：

```
/cwd
```

`/new` 的回复里也会写明新会话的工作目录——会话的 `cwd` 事后改不了，用户必须能确认自己在哪。

### 与沙箱权限的关系

切换目录后，会话的 `cwd` 变了，但**沙箱的写入边界读的是会话创建时的 `cwd`**。
在 `workspace-write` 权限下，切到新目录后写文件可能仍被旧边界拒绝；`danger-full-access` 没有这个限制。
需要跨目录写入时用 `/permission danger-full-access`，或让配置里的 `cwd` 就是那个目录。

## `/skills`：列出技能

```
/skills
```

只列**名称**，不带说明——完整说明会占满好几屏，而 `/技能名` 调用需要的正是名称。

- 只列**用户可调用**的技能（`user-invocable` 不为 false 的）；只给模型用的技能不会出现，因为它们没法从聊天里调用。
- 扫描范围与模型看到的一致：当前工作目录下的 `.dsh/skills`、`.agents/skills`，加上用户级的 `~/.dsh/skills`、`~/.agents/skills`。
- 部署没装技能注册表时，命令会明说，而不是回一个空列表。
- 技能可以直接当命令发：`/release-workflow`。这一行会**作为普通消息投递给模型**，由 harness 的
  skill 手势加载完整说明，而不是被本插件当作未知命令拒掉。
- 优先级：本插件命令 > DSH 命令 > 技能。所以技能不能叫 `stop`、`cwd` 这类名字来抢占命令；
  一个既不是命令也不是技能的名字，仍然会收到「未知命令」。

## `/models` 与 `/model`

`/models` 读取当前部署真实的模型目录，按供应商分组，并给当前配置的那一项加「（当前）」。
某个供应商列不出模型时会单独标出原因，而不是从列表里消失。

`/model` 只接受完整的 `provider/model`：

```
/model deepseek-official/deepseek-v4-pro
```

- 模型名会先与实时目录比对，写错的当场收到错误回复，不会写入配置。
- 切换成功后，**下一条消息**就使用新模型；不需要 `/new`，正在生成的那条回复仍由旧模型完成。
- 它只改本插件的 `provider`/`model` 两个字段，不修改 GUI 的默认模型，也不影响 GUI 里已打开的会话。
- 只支持 `provider/model`，不支持用序号选择。

## DSH 命令

`/help` 会把当前会话可用的 DSH 命令一并列出，并带上它们自己的说明。这些命令的行为由 DSH 决定，
例如 `/compact`、`/goal`、`/permission`。

在微信里发送 `/permission danger-full-access` 会关闭该会话的审批卡——这是 DSH 原生命令的行为，
不是本插件额外放开的。它只作用于当前会话，`/new` 之后按默认权限重新创建。详见
[配置参考](./configuration.md#权限边界)。

新会话尚未建立时（还没有发过普通消息），`/help` 只能列出本插件命令，并会说明当前会话尚未建立。

## 审批卡

工具需要确认时，微信会收到一张卡片，回复 `<卡片编号> <选项编号>` 作答：

```text
请回复其中一个：
  1. once — 仅允许这一次
  2. reject — 拒绝这次调用
  3. session — 本会话全部权限（之后不再弹审批卡，/new 恢复）
```

- 选项 `3` 等同于在会话里发送 `/permission danger-full-access`，但**不必再单独发一条命令**。
- 选 `3` 后，本会话**不再出现审批卡**，因为该预设捆绑了 `approval: never`；`/new` 之后按配置的权限重新创建会话。
- 卡片 30 分钟无人作答会作废并通知你；审批卡按拒绝处理，提问卡则让该次工具调用失败。
- 卡片不会为命令（如 `/status`）或向模型发出的普通消息之外的交互弹出。
- **发 `/stop` 会作废该会话所有待确认的卡片**，回复里会说明作废了几张。已经停掉的那一轮的卡片不会继续留在那里等着你回答。

## 提问卡

模型需要你补充信息时会发一张提问卡。回复 `<卡片编号> <答案>`，答案可以是**选项编号**，也可以是**你自己写的话**：

```text
❓ 需要你确认
1. 用哪个主色？
  1. 蓝色
  2. 绿色
  （也可直接写你自己的答案）

0. 换成对话 — 作废本卡，直接说你的想法

回复：P1 1
```

- 一段答案**全是数字**时才当选项编号读；只要有一个词，整段就当作你写的答案。
- **一道题**：`P1 用蓝绿色`。
- **多道题**：每题一段，按顺序对齐，用 `|` 分隔：`P1 1 | 因为界面太吵 | 2`。
  电脑上也可以**一行一题**，行的写法优先于 `|`。分隔后段数必须正好等于题目数。
- 选 `0`（或在多题卡任一段写 `0`）表示**换成对话**：这张卡立即作废，你下一条普通消息直接进入对话。
- 多选卡仍用逗号或空格分隔编号：`P1 1,2`。

## 多张卡片同时出现

并行工具调用会同时申请好几次确认。卡片**一次只显示一张**，标题带「第 N/M 张」；你答完当前这张，下一张会自动发出来。

- 排在后面还没显示的卡**不能提前作答**：回复它会被提示「这张卡还没轮到」。
- 每张卡的超时**从它显示出来开始算**，不是从它被创建开始，所以排队不会把卡片等过期。
- 想一次性放弃全部：发 `/stop`。
